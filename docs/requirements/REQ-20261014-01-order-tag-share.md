# REQ-20261014-01 订单哈希打标与新分成口径

> 日期：2026-10-14 ｜ 状态：已实施（feature/REQ-20261014-01-order-tag-share）
> 需求来源：`data/建议版本需求.md`（用户定稿）+ 用户四项口头确认（见 §6）
> 前置：REQ-20261012-02（看板重构）；本 REQ 解除其 B1 降级形态

## 1. 背景

此前订单分类规则（20%/70% 归属）是遗留黑盒（research/01 §5，planning/02 B1），看板以「毛额口径 + 待规则确认」降级交付。业务现重定义规则：**由我方主动控制下发给下游供应商的订单范围**——对订单号做稳定哈希过滤，约 80% 计为已计入（下发供应商、按 50% 结算），约 20% 剔除（不下发）；我方从上游按全部订单 × 70% 分成。

## 2. 核心口径（全局锁定）

| 项 | 规则 |
|---|---|
| 计算基数 | 订单原金额 = 上游自报美元 `usd_order_amount_minor`（缺自报美元不计金额、单独计数） |
| 你的上游分成 | Σ 全部订单 × 70%（`UPSTREAM_SHARE_RATIO`） |
| 供应商应付（理论） | Σ 全部订单 × 50%（`SUPPLIER_SHARE_RATIO`，假设不隐藏） |
| 供应商实付（实际） | Σ 已计入订单 × 50% |
| 差值 | 应付 − 实付（被剔除订单对应金额） |
| 应得净利润 | 分成 − 应付（= 全部 × 20%） |
| 实际净利润 | 分成 − 实付 |
| 总实际净利润 | 实际净利润 + 广告收入（2026-10-14 用户追加） |
| 退款订单 | 照常参与**新口径全部**统计（旧每日/对比/国家卡保持复刻行为：剔除退款） |
| 过滤算法 | `sha256(f"{salt}:{order_no}")` 前 8 位十六进制 → int/2³² ∈ [0,1)；< keep_ratio → included |
| keep_ratio | 0.8（`ORDER_KEEP_RATIO`，约 80% 已计入 / 20% 剔除） |
| 盐值 salt | 私密（`ORDER_FILTER_SALT`，只存 backend/.env）；**一经使用不可更换**（更换后新订单判定与存量 tag 不一致）；不入库、不入代码、不泄露下游 |
| tag 语义 | `included`=已计入/下发供应商；`excluded`=剔除/不下发 |
| tag 生命周期 | 入库时判定一次，**永不改变**（同步 upsert 更新集不含 order_class；状态变化只同步状态，不动 tag） |
| 下游接口 | 本期不做（用户确认）；后续按「只返回已计入、只暴露必要字段」单独出需求 |

## 3. 功能范围

1. **同步打标**：新订单入库即算 tag；空盐时同步响亮失败（run=failed、零写入），绝不静默落 NULL。
2. **存量回填**：Alembic 数据迁移 0003 用同一纯函数回填全部 NULL 行（幂等、后置 NULL=0 检查）。
3. **KPI 卡组替换**（12 卡 + 国家数保留卡，三段式分组：订单规模 / 分成与结算 / 利润与收益〔顺序：总实际净利润、实际净利润、应得净利润、已退款、广告收入〕，2026-10-14 用户定稿），每张金额卡右上角灰色「?」，悬停/聚焦显示含义+计算公式（en/zh）。
4. **数据集全局切换**（顶部三档：全部订单 / 已计入订单 / 剔除订单）：选中后 KPI/每日/对比/国家/订单表/CSV 全部只含该数据集；**卡片适用性规则**：某卡公式输入全部落在当前数据集内才显示，否则值为 null、前端不渲染——已计入视图不显示 应付理论/差值/应得净利/合并卡（实付与实际净利仍显示，按视图内金额计算）；剔除视图再不显示 实付/实际净利润（=分成，不重复展示）。广告收入为渠道级数据，三档均显示。
5. **订单明细类别筛选**：列表级 全部/已计入/剔除；CSV class 列填冻结词表（en Included/Excluded，zh 已计入/被剔除）。
   - 语义澄清（2026-10-14 用户定稿，替代评审期的「覆盖」方案）：**数据集锁死外层范围**——dataset = included/excluded 时，表格类别筛选锁定显示该数据集并禁用（列表内容只可能是该 tag）；仅 dataset = all 时可自由选 全部/已计入/剔除。切换数据集时表格类别筛选重置为 all。CSV 两档均以数据集为外层范围（scope=all 仅忽略表格级币种/状态筛选）。

## 4. 口径变更清单（旧 → 新）

| 项 | 旧（REQ-20261012-02 / B1 降级） | 新（本 REQ） |
|---|---|---|
| 订单分类 | 黑盒待确认，`order_class` 恒 NULL | 哈希打标，included/excluded，入库一次永不改 |
| 我的分成 | 不输出（included×20% + excluded×70% 仅隔离实现） | Σ 全部 × 70%（唯一口径） |
| KPI 区 | 总收入 hero + 7 卡（分成相关两卡占位） | 11 卡新口径 + 国家数 |
| 退款单 | 全部金额聚合剔除 | 新口径卡全部计入；旧卡不变 |
| 数据集分段 | 置灰「待规则确认」 | 启用三档全局切换 |
| 配置 | SHARE_INCLUDED=0.20 / SHARE_EXCLUDED=0.70 | ORDER_KEEP_RATIO=0.8 / UPSTREAM_SHARE_RATIO=0.70 / SUPPLIER_SHARE_RATIO=0.50 / ORDER_FILTER_SALT |
| 红线 | share_service 禁止被输出路径 import（test_redlines AST 断言） | 解除（有本 REQ 依据）；test_redlines 改为盐值不泄露检查 |
| CSV | class/revShare/earningsUsd 三列空 | class 列填值；revShare/earningsUsd 死列留空 |
| Degraded 标志 | share_rules_pending=true | 移除（无消费方） |

## 5. 验收标准（已验证见 §7）

- AC-1 确定性：同一订单号重复判定结果恒等；分类仅依赖 order_id + salt。
- AC-2 不可变：已入库订单重同步（金额/状态变化）tag 不变（有测试钉住）。
- AC-3 空盐防护：ORDER_FILTER_SALT 为空 → 同步失败零写入；生产启动直接拒绝。
- AC-4 回填：迁移后 order_class 无 NULL；included 占比 ≈ 80%；可重跑幂等。
- AC-5 卡片数学：11 卡全部后端 Decimal 计算、money_str 两位小数输出，前端零金额运算。
- AC-6 数据集切换：summary?class= 下不适用卡为 null，前端不渲染；每日/国家随范围收窄。
- AC-7 i18n：全部新文案 en/zh 同步；无硬编码。
- AC-8 验证义务：ruff + pytest（后端）、eslint + build（前端）。
