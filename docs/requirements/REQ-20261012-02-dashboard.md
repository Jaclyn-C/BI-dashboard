## 1. 背景与目标用户

### 1.1 背景

- 用户 2026-10-12 指示（原话要点）：「写完登录注册后，去 html 里看一下把 UI 都写了（和这个 html 一样，相当于重构）；还有什么是直接用上游数据的、不需要其他处理的也直接写」。映射为：HTML 全部界面行为 1:1 对标重构（A8/A9），加上「直接用上游数据、无需业务加工」的数据链路（A1/A2/A5）与聚合（A7）；分类器只建接口留空（A6）。
- 参考实现 `docs/reference/visualisation.html` 是浏览器端单文件：同时直连上游 netshort CPS（OAuth2）与前开发自建后端（api.tfctechnology.com），在前端做双源 diff 得出「已过滤/缺失」分类、按 20%/70% 算分成、完成全部聚合与 CSV 导出。本次重构后：**浏览器只访问我方后端**；上游凭据只存服务端；金额计算全部收进后端（Decimal）。
- **B1 红线约束**（planning/02 §3，不可协商）：订单分类规则确认前——分类器空实现；只有「全部订单」数据集；一切 ×20%/×70% 分成金额不产出（金额直接牵涉结算，宁出全量不出错钱）；相关 KPI/图表以毛额（gross）口径展示并明确标注；CSV class 列留空。
- **范围外**（本 REQ 不做）：A4 供应商报表服务（老契约兼容）、下游供给接口、分类规则实现本身（B1）、Phase 0 数据记录器、短剧/素材/播放接口、MD5 签名链路、refresh token 体系。图表技术选型（自绘 SVG vs 图表库）、内部 API 契约、库表字段设计、CSV 文件组装位置均归 architect 的 DESIGN 文档，本 REQ 只定行为。

## 2. 功能描述（用户故事）

- **US-1 数据自动同步**：作为运营，我希望订单与广告收益数据由后端自动定时同步落库，打开看板即有数据，不需要我手动拉取或等浏览器逐天请求。
- **US-2 看板总览（KPI）**：打开看板我能一眼看到总收入、订单毛额、订单数、国家数、广告收入（B1 期间分成类 KPI 以毛额/占位呈现，见第 3 节标注）。
- **US-3 每日收益**：我能看每日收益柱状图与数据表，在「估算（固定汇率）」与「上游美元」两种美元口径间对比（B1 期间为毛额口径）。
- **US-4 新旧美元口径对比**：我能核对旧静态汇率算法与上游自报美元的差异，确认美元口径切换的影响与可信度。
- **US-5 广告收益**：我能看到该渠道纯新用户的每日广告收益趋势。
- **US-6 国家分布**：我能看到收入来自哪些国家/地区、各币种构成与占比。
- **US-7 订单明细**：我能逐笔查看订单，按币种/状态筛选、按时间/币种/金额/美元排序、翻页浏览（类别筛选待规则确认后开放）。
- **US-8 CSV 导出**：我能把当前视图或区间内全部订单导出为 Excel 可直接打开的 CSV（无乱码、无公式注入风险）。
- **US-9 时间与数据集筛选**：我能按四预设或自定义区间（≤92 天）筛选；数据集在分类规则确认前只有「全部订单」一档。
- **US-10 手动刷新与状态可见**：我点 ↻ 能立即同步当前区间并看到加载进度、更新时间；数据不全、上游失败、今天数据未齐时都有明确提示，绝不白屏。
- **US-11 通用体验**：手机（375px）与电脑（1280px）、明暗两种外观、中英两种语言下看板都能完整使用。

## 3. 验收标准（可测试）

**B1 降级索引**（这些 AC 在分类规则确认前按毛额/占位口径验收；规则接入后替换为完整版，回归条件见 AC-CL3）：
AC-D1～D3、AC-K1～K3、AC-E4、AC-E7、AC-O1（类别列）、AC-O2（类别筛选）、AC-O8、AC-X1（类别筛选部分）、AC-X3、AC-AG5、AC-CL1～CL3。

金额展示默认货币格式 USD、随 locale 格式化；「毛额（gross）」= 订单上游自报美元金额（usdOrderAmount，最小单位）求和，不含任何分成比例。

### 3.1 登录墙与会话（衔接 REQ-20261012-01）

- **AC-G1** 未登录访问看板：重定向到登录页（REQ-01 AC-L3）；登录成功后进入看板并自动加载默认视图（近 7 天，见 AC-T2）。
- **AC-G2** 任一看板接口返回 401：提示「登录状态已过期，请重新登录」（对标 HTML `loginExpired`），返回登录页；重新登录后看板恢复且无需手动刷新以外的操作。
- **AC-G3** 点击退出按钮：清除会话并回到登录页（对标 HTML `logoutBtn`）；再次登录后从默认视图重新加载。

### 3.2 数据同步与状态行

- **AC-S1** 打开看板或切换时间范围：数据加载期间看板内容半透明（对标 `loadingdim`）且状态行显示加载态；若触发逐日同步任务，状态行显示「正在加载 {a}/{b} 天…」进度（对标 `loadingDays`）。
- **AC-S2** 加载完成：状态行显示「更新于 {t} · {n} 笔订单」（t 为最近同步完成时间、n 为区间内全部订单数），圆点为绿色成功态（对标 `updated` + `dot ok`）。
- **AC-S3** 后端定时同步默认每 30 分钟执行一次（D1），每次滚动重拉最近 3 天（含当日）订单与广告日汇总（D2）；同步幂等——同一天重跑不产生重复订单（以 orderId 去重 upsert）。
- **AC-S4** 点击 ↻ 刷新按钮：对当前筛选区间触发一次即时同步（不等下一次定时），期间呈现 AC-S1 加载态，完成后按 AC-S2 更新状态行（对标 HTML `refreshBtn` 清缓存重载行为，D4）。
- **AC-S5** 上游不可用或同步失败：看板继续展示已落库数据，不出现 500 或白屏；状态行显示失败态（红点/文案），页面顶部显示含「重试」按钮的横幅（对标错误横幅 + `connFailed`；CLAUDE.md 降级要求）。
- **AC-S6** 筛选区间包含最新可见日（含「今天」预设）：状态行区域出现常驻注记，说明上游同步有延迟、最新一天数据可能不全（D5；依据 planning/02 B5 与 research/01 §5.5；文案走 i18n）。
- **AC-S7** 任一时间窗在二分补全到最大深度后仍整页返回（truncated）：显示「数据不完整」警告横幅，说明部分窗口超出接口行数上限、合计可能偏低（对标 `partialTitle/partialBody`）。
- **AC-S8** createTime 按上游原值存储与展示（存储层不做任何时区换算）；订单表时间列表头标注 UTC（D6）；按日聚合以原值日期部分（即 UTC 日）为日界（对标 HTML `slice(0,10)`）；时间预设「今天」按浏览器本地日历日（对标 `todayStart()`）。
- **AC-S9** 广告收益同步失败：显示「广告收入不可用」警告横幅（对标 `adFailTitle`），订单类数据与展示不受影响。

### 3.3 时间筛选

- **AC-T1** 四个预设 chip（今天/近 7 天/近 14 天/近 30 天）：点击后切换区间并重新加载；选中 chip 呈 aria-pressed=true 与 ✓ 前缀样式（对标 `.chip[aria-pressed]`）。
- **AC-T2** 登录后默认视图为「近 7 天」（对标 boot `setPreset('7d')`）。
- **AC-T3** 自定义区间：起/止日期任一变更即生效；起>止自动交换；止超过今天钳制为今天；跨度超过 92 天自动将起点收缩为「止 − 91 天」（对标 `setCustomRange`，MAX_RANGE_DAYS=92）。
- **AC-T4** 日期输入框 max 属性为今天（不可选未来日期）；切换预设或自定义后 chips 选中态与输入框值保持同步（对标 `syncControls`）。
- **AC-T5** 切换时间范围、排序、筛选均将订单表页码重置为第 1 页（对标 `state.tablePage = 0`）。

### 3.4 数据集切换与分成红线（B1 降级）

- **AC-D1** 数据集分段控件保留三档入口；默认且唯一可点的是「全部订单」；「已过滤订单（20%）」「缺失订单（70%）」两档置灰（disabled、不可聚焦）、带「待规则确认」标注（B1；D7）。
- **AC-D2** 应用栏副标题在 B1 期间显示全量毛额口径说明（如「全部上游订单 · 毛额口径（分成规则待确认）」），不出现任何 20%/70% 分成表述（对标 `subAll` 的降级版）。
- **AC-D3** 分成金额零输出：全部看板 API 响应、页面渲染文案、图表数值、CSV 内容中不出现 ×20% 或 ×70% 的计算结果（可通过响应结构与导出文件自动化校验；B1 红线）。

### 3.15 上游客户端与订单接入（后端行为）

- **AC-U1** OAuth2 client-credentials 换票（HTTP Basic 方式）；token 缓存复用、到期前 60 秒主动刷新；遇 401（HTTP 层 401 或 HTTP 200 信封 code=401）丢弃缓存重换票并重试原请求一次，不循环重试（对标 HTML:878-944 与上游文档刷新建议）。
- **AC-U2** 订单窗口化拉取：按日窗口调用 `/open/order/list`（请求 pageSize=1000）；返回行数等于请求 pageSize 即判定可能截断 → 时间窗二分（最大深度 6、最小窗口 120 秒）补全；二分到底仍整页的窗口记录 truncated 标志并最终反映为 AC-S7 横幅（对标 `fetchUpstreamWindow`）。
- **AC-U3** 全量订单落库：上游 10 个字段全量存储（orderId, createTime, theaterId, chapterId, language, currencyType, amount, orderAmount, refundTime, promotionCode）；规范化层将 orderAmount 映射为 usdOrderAmount（语义=上游自报美元金额，最小单位）；amount=原币金额（最小单位）；createTime 原值存储（AC-S8）；同步幂等（重跑以 orderId 去重 upsert，不产生重复行）。
- **AC-U4** 广告收益代理：按区间调用 `/open/order/adSummary`，取行内 date（前 10 位为日）与 ad_revenue_dollars（**美元单位、非最小单位**，落库时统一口径换算）按日 upsert；与订单同一同步节奏，单次请求不二分（92 天 ≤ 92 行 < 请求页上限，无截断风险；D11）。
- **AC-U5** 出站调用白名单：运行时仅调用 3 个上游接口（/open/oauth2/token、/open/order/list、/open/order/adSummary）；代码中不存在对老后端（api.tfctechnology.com）任何运行时调用（代码审查 + 网络面板可验证；planning/02 硬性约束 1/2）。
- **AC-U6** 金额纪律：同步换算、聚合、对比等一切金额/汇率计算使用 `decimal.Decimal`、数据库金额列 `Numeric`，禁止 float；前端不做任何金额运算，仅渲染后端给定值（CLAUDE.md 第 4 节）。
- **AC-U7** 拉取并发默认 4（配置化）；上游 429/超时记录日志并按 AC-S5 降级，不无限重试（对标 `FETCH_CONCURRENCY` 与 planning/02 风险表）。
