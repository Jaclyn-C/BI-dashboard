## 业务概述

业务链路：**上游 netshort（短剧 CPS 平台）→ 我方处理 → 下游供应商**。看板展示订单与广告收益，按分成规则计算收益；重构后新增「处理 → 下游供给」链路（规则待需求逐步给出）。

## 收益分成（核心口径，REQ-20261014-01 定稿 2026-10-14）

- 业务链路模型：上游按**全部订单 × 70%** 付我方分成；订单按哈希过滤后约 **80% 已计入（included，下发供应商）**、**20% 剔除（excluded，不下发）**；供应商按**已计入订单 × 50%** 结算
- 计算基数 = 上游自报美元 `usd_order_amount_minor`（缺自报美元不计金额、单独计数）
- 卡片口径：差值=应付−实付；应得净利=全部×20%；实际净利=分成−实付；**退款单照常参与新口径全部统计**（旧每日/对比/国家卡保持复刻行为：剔除退款）
- **过滤规则（已定，不再是黑盒）**：`sha256(salt:order_no)` 前 8 位十六进制 → int/2³² ∈ [0,1)，< 0.8（ORDER_KEEP_RATIO）→ included。salt 私密只存 .env，**一经使用不可更换**；tag 入库算一次**永不改变**（upsert 更新集不含 order_class）
- 实测分布：22,758 笔存量回填 included 占比 79.76%；万级合成 80.29%
- 数据集三档全局切换（全部/已计入/剔除）：不适用卡片值为 null、前端不渲染（适用性规则见 REQ §3）

## KPI 口径（REQ-20261014-01 新卡组，基数=上游自报美元，含退款单）

| KPI | 公式 |
|---|---|
| 订单总数 / 订单总金额 | count(全部) / Σ usd（aux：已完成 n · 退款 m） |
| 你的分成金额（70%） | Σ 全部 × 70% |
| 供应商应付（理论）/ 实付（实际） | Σ 全部 × 50% / Σ 已计入 × 50% |
| 差值（隐藏省下的钱） | 应付 − 实付 |
| 应得净利润 / 实际净利润 / 总实际净利润 | 分成 − 应付（=全部×20%）/ 分成 − 实付 / 实际净利润 + 广告收入 |
| 已退款总金额 | Σ 已退款订单 usd |
| 计入/剔除合并卡 | 两类各自 count 与 Σ usd |
| 广告收入 | 上游按日上报的渠道新用户广告收益（USD，`/open/order/adSummary`），口径不变 |
| 国家数 | 订单 language 推断的国家数（保留卡） |
| 每日双口径 / 新旧对比 / 国家分布 | 复刻行为不变（剔除退款、缺 usd 剔除），仅随数据集切换收窄范围 |

## 新旧美元口径对比（conv 卡片）

- **旧口径**：原生金额 × 静态汇率表（原表来自 export_orders.py，约 30 币种、2026-08 估值）；无汇率币种直接丢弃（与旧导出逻辑一致）
- **新口径**：上游自报美元额（上游 `orderAmount`，老后端改名 `usdOrderAmount`）；无自报值的 completed 订单被排除并提示
- 一致性阈值：两者相差 ≤ 0.5% 视为 agree

## 订单事实

- CSV 字段（13 列）：orderId, createTime, theaterId, chapterId, country, language, currency, amount, estUsd, class, revShare, earningsUsd, status, promotionCode
- 上游原始字段：orderId, createTime, theaterId, chapterId, language, currencyType, amount, orderAmount(USD), refundTime, promotionCode（country/estUsd/class/revShare/earningsUsd/status 是看板派生）
- status：Completed / Returned（returned 判定 = refundTime 非空）
- 国家由订单 language 推断（countryOf 映射），未知归 Unknown
- **createTime 疑似 UTC 且有数十分钟同步延迟（B5）**：存储层存上游原值，展示层定时区，不在存储层猜——「今天」的数据永远不全，完整数据次日才有
