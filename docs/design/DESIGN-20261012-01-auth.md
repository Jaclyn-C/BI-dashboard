## 1. 技术方案总览

### 1.1 模块归属与分层

```
浏览器 (React SPA)
  │  /api/v1/auth/**（JSON，Bearer token）
  ▼
backend/app/
  ├─ api/v1/auth.py          路由层（薄：参数解析 → 调 service → 组响应）
  │    └─ deps.py            get_current_user 依赖（JWT 解码 + pwd_ver 校验）
  ├─ services/
  │    ├─ password_service   argon2id 哈希/校验
  │    ├─ token_service      JWT 签发/解码（8h，无 refresh）
  │    ├─ code_service       验证码生成/校验/频率限制（DB 计数）
  │    └─ email_sender       EmailSender 接口 + SMTP 实现 + 开发日志降级
  ├─ models/                 User、VerificationCode（SQLAlchemy 2）
  └─ schemas/auth.py         Pydantic 入出参（校验规则与前端同源）
```

分层遵守 CLAUDE.md §4：路由不写业务逻辑，service 不感知 HTTP。本需求不涉及金额、不涉及上游调用（`upstream/` 只留目录骨架）。

### 1.2 关键流程

**注册**：发码（`register` 用途，查重邮箱未注册 → 限流检查 → 落码记录 → 发信）→ 用户提交邮箱+昵称+密码+验证码 → code_service 校验通过（先验码后建号）→ 同一事务内建用户 + 标记验证码已消费 → 直接签发 token（自动登录）。

**登录**：邮箱+密码 → argon2 校验（账号不存在时用哑哈希跑一次校验抹平时序差）→ 签发 JWT（含 `pwd_ver` claim）。

**找回密码**：发码（`reset` 用途，要求邮箱已注册）→ 提交邮箱+验证码+新密码 → 验码通过 → 同一事务内更新密码哈希 + `credential_version += 1` + 标记验证码已消费 → 该账号全部旧 token 因 `pwd_ver` 不匹配立即失效 → 用户用新密码重新登录。

**会话**：token 存 sessionStorage（对标参考实现 `visualisation.html:827-829`）；任一 API 401 → 清 token → 跳 `/login?expired=1` 显示"登录状态已过期"。

### 1.3 选型决策记录（含理由与备选）

| # | 决策 | 理由 | 备选（不采用原因） |
|---|---|---|---|
| D1 | 密码哈希 **argon2id**（`argon2-cffi` 的 `PasswordHasher`，库默认参数 t=3/m=64MiB/p=4） | OWASP 首选算法；无 bcrypt 的 72 字节输入截断问题（中文密码 64 字符可达 192 字节，bcrypt 会静默截断）；库持续维护（RQ-2 已拍板定稿） | bcrypt：成熟但需预哈希绕 72 字节限制，多一步易被后续维护者漏掉；passlib：2020 年起无维护，与新版 bcrypt 不兼容，直接排除 |
| D2 | token = **JWT（PyJWT，HS256）**，有效期 8h，无 refresh；旧 token 失效机制 = claim 内嵌 `pwd_ver`，与 `users.credential_version` 比对 | 无状态、实现最小；重置密码 bump 版本号即可让全部旧 token 失效（AC-P3/Q7），无需 denylist 表 | 服务端 session 表：违背无状态选型初衷，内部规模不需要；jti denylist：仅 logout 场景有用，本期不做服务端登出（见 §3.7） |
| D3 | 验证码存 **PostgreSQL**（HMAC-SHA256 摘要 + 每码独立过期时间 + 尝试计数） | 项目无 Redis 且不引入；量级极小（内部用户） | Redis：引入新组件，违反约束 |
| D4 | 频率限制 = **DB 计数**（同邮箱跨用途共用：60s 冷却 + 每小时 5 封） | Q4 定稿注册/找回共用通道与限额；`verification_codes` 表按 `email` 聚合计数即可，无新表 | 内存计数：多进程/重启即失效 |
| D5 | SMTP = **aiosmtplib**（异步原生，路由内直接 await，无线程池包装代码） | 技术栈整体 async（FastAPI/httpx）；smtplib 是阻塞库，async 路由里需 `run_in_threadpool` 包装 | smtplib + threadpool：可行但多一层包装，收益为零 |
| D6 | 后端依赖管理 = **pyproject.toml + uv**（生成 uv.lock 锁定） | 锁文件保证可复现安装；安装速度快；Docker 构建友好；PEP 621 标准，后续换工具无锁定 | requirements.txt：无锁文件哈希，可复现性弱 |
| D7 | 前端 i18n = **react-i18next** | 参考实现 `{a}/{b}` 插值、en 兜底、后续看板约百条文案都要用；标准库级事实方案 | 自写 40 行 t()：本期够用但看板阶段必然重做，不划算 |
| D8 | 样式 = **纯 CSS**（迁移参考 HTML 的 `:root` 变量表 + `.logincard` 系列类名），不引 UI 框架 | 三个表单页 + 一套既有变量体系，UI 框架只会带来覆盖成本；参考实现本身就是纯 CSS，类名可直接平移，看板后续图表也是自绘路线 | Ant Design/MUI：主题体系与既有变量表冲突，体积不划算 |
| D9 | 登录响应保留 **`access_token`** 键名（另加 `token_type`/`expires_in`/`user`，纯增量） | 与参考实现的响应形状延续，前端迁移成本低；老契约兼容 shim 已拍板不做（RQ-1，§3.7） | 完全新形状（如 `{token}`）：无收益且丢延续性 |

## 3. API 契约清单（前后端唯一真源）

### 3.1 通用约定

- 前缀 `/api/v1/auth/**`；请求/响应体均为 `application/json`（UTF-8）。
- 时间戳一律 UTC（ISO 8601，带 `Z` 或偏移）；前端展示层转本地时区。
- 邮箱入参两端统一 **去首尾空白 + 转小写** 后处理（大小写不同视为同一邮箱）。

### 3.2 响应形状

**成功**：直接返回资源 JSON（不套信封）。

**失败**：统一错误信封（`main.py` 异常处理器保证所有错误走此形状，包括 FastAPI 原生 422）：

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "request validation failed",
    "details": [ { "field": "password", "msg": "…" } ]
  }
}
```

非校验类错误无 `details` 字段（如 `{"error": {"code": "INVALID_CREDENTIALS", "message": "invalid email or password"}}`）。

`code` 为机器码（前端映射 i18n key `auth.error.<code>`，映射缺失时兜底显示 `message` 或网络错误文案）；`message` 为英文兜底文案；`details` 仅 `VALIDATION_ERROR` 时出现（字段级）。

### 3.3 接口一览

#### (1) 发送注册验证码

`POST /api/v1/auth/register/code`

- 入参：`{ "email": "user@example.com" }`（必填，邮箱格式，≤254 字符）
- 出参：`204 No Content`
- 逻辑：**限流检查先于邮箱查重**（只读检查，见 §4.3——重复探测同一邮箱先撞 429，再轮到 409/404）→ 邮箱已注册 → 409 → 落码（purpose=register）→ 发信；发信失败回滚码记录（冷却不被消耗，计数以落库成功为准）→ 502
- 错误：`422 VALIDATION_ERROR`；`409 EMAIL_ALREADY_REGISTERED`；`429 CODE_SEND_COOLDOWN` / `429 CODE_SEND_HOURLY_LIMIT`（均带 `Retry-After` 头，秒）；`502 EMAIL_SEND_FAILED`

#### (2) 注册

`POST /api/v1/auth/register`

- 入参：`{ "email", "nickname", "password", "code" }`（四项全必填；规则见 §5.2）
- 出参：`201 Created`（自动登录，同登录响应；`user` 载荷四字段 id/email/nickname/created_at 与 (6) `/me` 完全同形，评审 P6 统一）：

```json
{
  "access_token": "eyJ…",
  "token_type": "Bearer",
  "expires_in": 28800,
  "user": { "id": 1, "email": "user@example.com", "nickname": "小明", "created_at": "2026-10-12T08:00:00Z" }
}
```

- 逻辑：**先验码后建号**（AC-R5：验证码无效时账号不创建）；邮箱占用双保险（业务查重 + DB 唯一约束，并发撞约束也回 409）
- 错误：`409 EMAIL_ALREADY_REGISTERED`；`400 VERIFICATION_CODE_INVALID`（码错/过期/超 5 次尝试统一此码）；`422 VALIDATION_ERROR`

#### (3) 登录

`POST /api/v1/auth/login`

- 入参：`{ "email", "password" }`
- 出参：`200 OK`，形状同 (2) 的响应（`user` + token）
- 逻辑：邮箱或密码任一错误 → **统一模糊 401**（不区分哪项错，AC-L2）；账号不存在时对哑哈希做一次 argon2 校验抹平时序
- 错误：`401 INVALID_CREDENTIALS`；`422 VALIDATION_ERROR`

#### (4) 发送重置验证码

`POST /api/v1/auth/password/code`

- 入参：`{ "email" }`
- 出参：`204 No Content`
- 逻辑：同 (1)（限流只读检查同样先于邮箱查重）但要求邮箱**已注册**（未注册 → 404，AC-P5 明确提示策略）；限流与注册共用（按 email 跨 purpose 计数）
- 错误：`404 EMAIL_NOT_REGISTERED`；`429`（同上）；`502 EMAIL_SEND_FAILED`；`422 VALIDATION_ERROR`

#### (5) 重置密码

`POST /api/v1/auth/password/reset`

- 入参：`{ "email", "code", "new_password" }`（三项缺一不可，AC-P1）
- 出参：`204 No Content`（前端提示成功后引导去登录页）
- 逻辑：验码通过 → 同一事务：更新密码哈希 + `credential_version += 1` + 消费验证码 → 全部旧 token 立即失效（AC-P3/Q7）
- 错误：`404 EMAIL_NOT_REGISTERED`；`400 VERIFICATION_CODE_INVALID`；`422 VALIDATION_ERROR`

#### (6) 获取当前用户

`GET /api/v1/auth/me`（Header：`Authorization: Bearer <token>`）

- 出参：`200 OK`：`{ "id", "email", "nickname", "created_at" }`
- 用途：前端启动恢复会话、校验 token 存活；后续所有受保护接口复用同一 `get_current_user` 依赖（本期看板尚无业务接口，此依赖即保护模式的样板）
- 错误：`401 UNAUTHORIZED`（未带/伪造/过期 token，或 `pwd_ver` 已不匹配）

### 3.4 错误码总表

| code | HTTP | 触发场景 |
|---|---|---|
| `VALIDATION_ERROR` | 422 | 入参格式/规则不符（details 给字段级信息） |
| `INVALID_CREDENTIALS` | 401 | 登录邮箱或密码错误（模糊提示） |
| `UNAUTHORIZED` | 401 | 受保护接口未带/无效/过期/已被重置作废的 token |
| `EMAIL_ALREADY_REGISTERED` | 409 | 注册发码或注册时邮箱已存在 |
| `EMAIL_NOT_REGISTERED` | 404 | 找回发码或重置时邮箱未注册 |
| `NOT_FOUND` | 404 | 路由不存在（FastAPI 默认 404 亦经统一信封处理器输出） |
| `VERIFICATION_CODE_INVALID` | 400 | 验证码错误 / 已过期 / 超 5 次尝试 / 无有效记录 |
| `CODE_SEND_COOLDOWN` | 429 | 同邮箱 60s 内重复发码（`Retry-After`） |
| `CODE_SEND_HOURLY_LIMIT` | 429 | 同邮箱 1 小时超 5 封（`Retry-After`） |
| `EMAIL_SEND_FAILED` | 502 | SMTP 已配置但投递失败；或生产环境未配 SMTP |
| `INTERNAL_ERROR` | 500 | 兜底（不泄漏内部细节） |

### 3.5 登出（取舍说明）

**不设服务端登出接口。** 理由：JWT 无状态、无 refresh token，服务端登出需引入 jti denylist 表——为内部小规模系统新增一张表与每请求查询成本，收益仅是"提前作废一个最多 8 小时的 token"。登出 = 前端清 sessionStorage token + 跳 `/login`（对标参考实现 `clearToken` 行为，HTML:850-853）。若未来需要"主动踢下线/改密即时全端失效且无版本列"再加 denylist，当前 `credential_version` 已覆盖重置密码场景（Q7）。

### 3.6 验证码邮件

中英双语并列（Q9，不依赖界面语言）：主题双语；正文两段（EN/中文），含 6 位验证码、用途（注册/重置）、"10 分钟内有效"。文案放后端常量（i18n 仅约束前端 UI，邮件文案不走前端 i18n 体系），backend-task 中作为 `email_sender` 模块的模板常量实现。

### 3.7 与老后端契约的差异（定稿：不做兼容 shim）

老后端 `POST /auth/login`：`{"username","password"}` → `{"access_token"}`（research/01 §4.2、planning/02 A3）。新系统：字段 `username`→`email`（REQ 定稿：账号=邮箱）、路径不同（`/api/v1/auth/login`）、响应保留 `access_token` 键名并增量扩展（D9）。**是否提供老路径兼容 shim 已拍板（2026-10-12，RQ-1）：不做。** 本期新契约唯一消费方是自建前端；B4 供应商账号迁移阶段如确需老形状，届时以增量 REQ 增加兼容路由（纯增量，不破坏本契约）。

## 4. 数据模型与迁移方案

### 4.1 users

| 列 | 类型 | 约束/说明 |
|---|---|---|
| `id` | BigInteger | PK，identity 自增 |
| `email` | String(255) | **UNIQUE**（`uq_users_email`，存规范化小写）；非空 |
| `nickname` | String(30) | 非空；显示用途，不唯一（Q5） |
| `password_hash` | String(255) | 非空；argon2id 摘要（含算法参数与盐，PHC 字符串），**永不存明文** |
| `credential_version` | Integer | 非空，默认 1；重置密码 +1，用于作废旧 token |
| `last_login_at` | DateTime(timezone=True) | 可空；注册与登录时更新 |
| `created_at` / `updated_at` | DateTime(timezone=True) | 非空，默认 `now()`（UTC）/ 自动更新 |

### 4.2 verification_codes

| 列 | 类型 | 约束/说明 |
|---|---|---|
| `id` | BigInteger | PK，identity |
| `email` | String(255) | 非空，规范化小写（**不建 FK**：注册场景用户尚不存在） |
| `purpose` | Enum('register','reset') | 非空；PG 原生 enum 或 VARCHAR+CHECK（迁移可逆性优先 → VARCHAR(16)+CHECK） |
| `code_hash` | String(64) | 非空；`HMAC-SHA256(code, 密钥派生自 SECRET_KEY)` 十六进制——无服务端密钥无法离线爆破 6 位码 |
| `attempts` | Integer | 非空，默认 0；校验失败 +1，达 5 作废（Q3） |
| `expires_at` | DateTime(timezone=True) | 非空；`created_at + 10min` |
| `consumed_at` | DateTime(timezone=True) | 可空；验证成功/被新码顶替/尝试耗尽时打点 |
| `created_at` | DateTime(timezone=True) | 非空，默认 now()（UTC）——限流计数的锚点 |

索引：`ix_verification_codes_email_created (email, created_at)`（限流计数查询）；`ix_verification_codes_email_purpose_active (email, purpose) WHERE consumed_at IS NULL`（partial index，取最新有效码）。**不存验证码明文**（AC-S2：明文只出现在邮件与开发日志两个出口）。

### 4.3 状态与生命周期规则

- **发新码**（步骤顺序，评审 P1 修复）：① 检查限流——按 email 跨 purpose **只读**计数（`created_at > now-60s` 有记录 → 冷却 429；`now-1h` 内 ≥5 条 → 超限 429）；② 作废该 (email, purpose) 所有未消费码（`consumed_at=now`）；③ 插入新码。限流检查位于邮箱查重与任何写入**之前**（重复探测同一邮箱先撞 429）；计数以**落库成功**为准——只读检查不改写任何数据，发信失败则整个事务回滚，冷却不被消耗。
- **验码**：取该 (email, purpose) 最新未消费码；无 / 已过期 / `attempts≥5` → `VERIFICATION_CODE_INVALID`；不匹配 → `attempts += 1`（行级 UPDATE 自增，防并发绕过尝试上限）后同样报错；匹配 → 打 `consumed_at`，进业务事务（建号或改密）。
- **过期码再提交仍被拒**（AC-R5）：`expires_at` 判定 + 已消费即无效，无"复活"路径。
- **清理**：本期不引入后台调度；发码事务内顺带 `DELETE` 该 email 24h 前的已消费/已过期记录（机会式清理，量级下足够）。

### 4.4 Alembic

- `alembic init` 后 `env.py` 接 `settings.database_url` 与 `Base.metadata`（所有模型在 `models/__init__.py` 导入）。
- 首个迁移 `0001_auth_baseline`：`alembic revision --autogenerate` 生成后人工核对（两表 + 两普通索引 + 一 partial 索引 + 唯一约束 + CHECK），`alembic upgrade head` 在 dev 库验证可升级/可降级（`downgrade base`）。
- 后续任何模型变更照 CLAUDE.md §4 流程：autogenerate + 人工检查，迁移是数据库变更唯一入口。

### 5.5 请求层与 401 处理

`src/api/client.js`：`baseURL='/api/v1'`（dev 走 Vite 代理，生产同源相对路径）；自动注入 `Authorization: Bearer`（token 存取 sessionStorage——RQ-3 定稿；key 沿用 reference 的 `vis_token::<base>` 命名风格定为 `pd_token`）；统一解析 §3.2 错误信封为 `ApiError{code,message,status}`；网络异常 → `ApiError{code:'NETWORK'}`；**任何 401**（除登录接口自身）→ 清 token → 跳 `/login?expired=1`（AC-L4，行为对标参考 HTML `api()` 的 401 分支，HTML:862-865）。组件内禁止裸 fetch 与硬编码地址（CLAUDE.md 禁止事项 4）。

### 5.6 登录记忆：邮箱始终记 + 密码按勾选（AC-L5，纯前端 localStorage，后端零改动）

- **邮箱始终记住**：任一次登录成功后，邮箱即写入 localStorage（key `pd_remember_email`）；下次打开登录页自动填充邮箱——这是登录页**默认行为**，与任何勾选无关。
- **密码按勾选决定**：登录页勾选框「记住密码 / Remember password」**默认不勾**，且**只管密码**。勾选并登录成功 → 密码一并写入 localStorage（key `pd_remember_pass`，存储为 `encodeURIComponent + base64` 编码混淆，代码注释如实说明"仅防肉眼直读，非加密"）；下次打开登录页邮箱+密码均已填好，直接点击登录即可。未勾选登录成功 → 清除已存密码（若有），仅保留邮箱记忆；取消勾选后再登录 → 触发清除。
- **封装**：`src/utils/remember.js`（`rememberEmail` / `rememberPassword` / `clearPassword` / `loadRemembered`），登录页仅在挂载（读回填）与登录成功回调（存/清）处调用，组件不直接操作 localStorage。
- **token 分离**：token 本体仍走 sessionStorage（RQ-3 定稿），与上述记忆 key 分离、生命周期互不影响；退出登录**不清除**记忆（记住的是输入项，不是会话）。
- **安全备注**：编码 ≠ 加密，密码记忆等价于本机明文级暴露，设备共用场景风险由用户自担；默认不勾选即为缓解，用户主动勾选视为选择承担。

## 6. 安全设计

1. **登录模糊提示**：`INVALID_CREDENTIALS` 单一错误码覆盖"邮箱不存在/密码错误"；账号不存在时跑一次哑 argon2 校验抹平时序差，响应时间不可区分（AC-L2）。
2. **枚举暴露面**（REQ 定稿的显式策略，如实记录）：注册报"邮箱已注册"（409）、找回报"邮箱未注册"（404）——与登录的模糊策略有意不对称（AC-R4/AC-P5 明确要求）。本期按 REQ 执行；若未来对外开放注册需重评。
3. **验证码**：明文只在两个出口——邮件、开发日志（AC-S2）；DB 只存 HMAC-SHA256 摘要（密钥服务端派生）；10 分钟过期 + 5 次尝试上限 + 发码双限流；不在任何 API 响应体回传。
4. **日志降级安全阀**：`LogEmailSender` 仅当 `SMTP_HOST` 为空 **且** `ENVIRONMENT=development` 时启用；生产未配 SMTP 一律 `EMAIL_SEND_FAILED`（502），验证码永不进生产日志。
5. **密码**：argon2id（D1）；Pydantic schema 中密码字段用 `SecretStr`，杜绝默认 repr 泄漏进日志/异常栈；全链路（路由/服务/日志/异常处理器）不落密码明文（AC-S1）；失败响应不含密码相关字段。
6. **凭据管理**：`SECRET_KEY`/SMTP/DB 凭据全部 `.env`，模板进根 `.env.example`（占位无真实值，AC-S3）；gitignore 覆盖 `.env` 及 `__pycache__`/`.venv`/`node_modules`/`dist` 等产物；`uv.lock` 与 uv 配置一并入库。
7. **注册先验邮箱归属**：验证码验证通过才建号（AC-R5），未验证邮箱无任何 user 行残留（验码失败事务不建号）。
8. **token**：HS256 + `SECRET_KEY`（≥32 字符随机）；claim 最小化 `{sub, iat, exp, pwd_ver}`；`pwd_ver` 与 `credential_version` 不符即 401（重置密码全端失效，Q7）；8h 短寿命 + 无 refresh。
9. **唯一性双保险**：邮箱唯一约束（DB 层）+ 业务查重（AC-S4），并发注册撞唯一约束同样返回友好 409。
10. **CORS**：dev 白名单 `http://localhost:5173`（走代理后其实同源，白名单是冗余保险）；生产反代同源部署，`CORS_ORIGINS` 收紧为空。
