# 部署指南（傻瓜式）

> 目标读者：没做过服务器运维的人。全部流程 = 买 2 样东西 + 跑 1 条命令 + 填几个配置。
> 形态：单台服务器 Docker Compose（PostgreSQL + FastAPI + Caddy 反代/自动 HTTPS），月成本约 25 元。
> 首次部署约 30 分钟（含等 DNS 生效）。
> 省钱变体：只在用户访问时开机、月底释放（阿里云按量 + 节省停机，月 ¥10-25；不用域名、纯 IP 访问则国内节点也免备案），见《[按量开关部署手册](按量开关部署手册.md)》，其首次部署复用本指南 §3 起。

## 0. 要买什么

| 买什么 | 推荐选择 | 大约价格 | 为什么 |
|---|---|---|---|
| 服务器 | 腾讯云「轻量应用服务器」**香港**节点，2核2G（活动套餐） | 约 288 元/年 | 免备案；国内访问快；微信支付；2G 内存跑本项目（<10 人访问）足够 |
| 域名 | 任意注册商的 .top / .xyz 等便宜后缀（腾讯云、阿里云、Namesilo 均可） | 约 10 元/年 | HTTPS 证书需要域名；供应商对接也需要正规域名 |

- **为什么不是国内节点**：国内服务器 80/443 端口必须先 ICP 备案（1-2 周），香港不用。
- **更省钱的备选**：RackNerd 等美国 VPS（约 $20/年），但国内打开看板明显变慢，不推荐给要看 daily 报表的场景。
- **数据量说明**：订单数据几十万到几百万行也就几个 GB，轻量自带 SSD 盘够用很久；`backups/` 保留 14 份同样占不了多少。真到盘快满（`df -h` 看）再升配或换大套餐，数据卷可迁移。

## 1. 买服务器（约 10 分钟）

1. 打开 https://console.cloud.tencent.com/lighthouse → 新建。
2. 地域选**香港**，套餐选 2核2G 最低档，镜像选 **Ubuntu 24.04**（纯净系统即可，不用预装 Docker，脚本会装）。
3. 付款后在控制台看到**公网 IP**，记下来。
4. 同一页面 → 防火墙 → 确认放行端口：`22`（SSH）、`80`（HTTP）、`443`（HTTPS）——默认 22/80/443 都已放行，一般不用动。

## 2. 买域名并解析（约 10 分钟 + 等生效）

1. 任意注册商买一个便宜域名（如 `yourname.top`）。
2. 进 DNS 解析（域名管理 → 解析记录）加一条：
   - 类型 `A`，主机记录 `@`（或你想用的子域名如 `db`），记录值 = 服务器公网 IP。
3. 等 5-30 分钟生效（`ping 你的域名` 返回服务器 IP 即生效）。

## 3. 一键部署（在你自己的电脑上跑）

前提：本机装有 Git Bash（Windows 装完 Git 就有）或 Linux/macOS 终端，且能 `ssh root@服务器IP` 登录（首次登录密码在腾讯云控制台「重置密码」处设置）。

在项目根目录执行：

```bash
bash deploy/deploy.sh root@服务器IP
```

这条命令会：上传代码 → 服务器装 Docker → 生成生产 `.env`（三个密钥自动随机生成，**其中 ORDER_FILTER_SALT 和数据库密码生成后永不可换**）→ 构建镜像 → 启动。

**首跑预期会停下来报一句「请先编辑 .env 填 DOMAIN」——这是正常的**，继续第 4 步。

## 4. 填 3 处配置（服务器上，约 5 分钟）

```bash
ssh root@服务器IP
nano /opt/partner-dashboard/.env
```

对照下表填（其余行不用动）：

| 配置项 | 填什么 | 不填的后果 |
|---|---|---|
| `DOMAIN=` | 你的域名（如 `yourname.top`） | Caddy 起不来，部署脚本会拦住 |
| `SMTP_*` 六项 | 发件邮箱。QQ 邮箱：`smtp.qq.com` / `465` / 邮箱地址 / **授权码**（设置→账户→开启 SMTP 获得）/ 同邮箱地址 / `false` / `true` | 收不到验证码 → 谁都注册/登录不了 |
| `UPSTREAM_CLIENT_ID` / `UPSTREAM_CLIENT_SECRET` | 上游 netshort 的凭据（照抄你本地开发 `.env` 里的同名两行） | 不同步订单，看板无数据 |

保存退出（nano：`Ctrl+O` 回车，`Ctrl+X`），然后**在自己电脑上再跑一次**：

```bash
bash deploy/deploy.sh root@服务器IP
```

这次会跑完并打印「部署完成：https://你的域名」。

## 5. 验证清单

- [ ] 浏览器打开 `https://你的域名` → 出现登录页（首次证书签发可能要等 1 分钟，报证书错误就稍等再刷新）
- [ ] 注册：填邮箱 → 收验证码 → 设密码 → 进入看板（此时若上游凭据已配，首次同步回填 92 天数据，需要几分钟到几十分钟）
- [ ] 打开 `https://你的域名/docs` → FastAPI 接口文档（给下游供应商看的）
- [ ] 服务器上 `docker compose -f compose.prod.yaml ps` → 三个容器都是 running/healthy

## 6. 备份（一次性配置，2 分钟）

服务器上执行：

```bash
crontab -e
# 加一行（每天 04:10 备份数据库，保留 14 份）：
10 4 * * * bash /opt/partner-dashboard/deploy/backup.sh
```

备份文件在服务器 `/opt/partner-dashboard/backups/`。**同机备份防误删不防机器挂**，建议每月手动下载一份到本地：
`scp root@服务器IP:/opt/partner-dashboard/backups/pd-最新日期.sql.gz .`

## 7. 日常操作速查（都在服务器 /opt/partner-dashboard 下）

```bash
docker compose -f compose.prod.yaml ps          # 看状态
docker compose -f compose.prod.yaml logs -f api # 看后端日志（同步报错看这里）
docker compose -f compose.prod.yaml restart     # 重启全部
docker compose -f compose.prod.yaml down        # 停止（数据不丢）
```

**升级发版**：本地改完代码提交后，再跑一次 `bash deploy/deploy.sh root@服务器IP`——同一条命令，数据卷和 .env 不受影响。

**恢复备份**：`gunzip < backups/pd-日期.sql.gz | docker compose -f compose.prod.yaml exec -T postgres psql -U pd pd`

## 8. 常见问题

| 症状 | 原因与处理 |
|---|---|
| 浏览器打不开/证书错误 | DNS 未生效或防火墙没放行 80/443；`ping 域名` 核对 IP；等 10 分钟再试 |
| 收不到验证码 | `.env` 的 SMTP 没配对（QQ 邮箱必须用「授权码」不是登录密码，`SMTP_SSL=true`）；改完 `docker compose -f compose.prod.yaml up -d` 重建生效 |
| 看板一直没数据 | `UPSTREAM_CLIENT_ID/SECRET` 没填或填错；`docker compose -f compose.prod.yaml logs api` 看同步报错 |
| 想改域名 | 改服务器 `.env` 的 `DOMAIN`，再 `up -d`（新域名要重新解析） |
| 磁盘满 | `df -h` 确认；清旧备份 `ls backups/`，或升配套餐后数据卷随实例迁移 |
